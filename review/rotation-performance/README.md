# Оптимизация вращения без смены дизайна

База: 5292fc96830f8b88ab0e3875628a22cbc28ce51a. Публикация не выполнялась.

## Найденные причины

- Вся отрисовка была ограничена 30 FPS, включая активное вращение мышью.
- Масштаб canvas принудительно доходил до 2× даже на обычном 1× экране. При модальном окне около 1180×673 отрисовывались 2135×1217 = 2,60 млн пикселей.
- Геометрия уже использует instancing; тени кешируются, фон за открытым просмотрщиком останавливается. Эти существующие оптимизации сохранены.

## Что изменено

- Разрешение учитывает реальный devicePixelRatio вместо обязательного supersampling на обычном мониторе.
- Во время перетаскивания, масштабирования и анимации смены ракурса используется отдельный бюджет около 0,75 млн пикселей, до 1× (на очень больших окнах нижняя граница масштаба 0,65).
- Через 650 мс после окончания жеста, по завершении анимации, возвращается обычное разрешение. На 2× дисплее восстановление проверено в настоящем браузере.
- При управлении разрешена отрисовка до 60 FPS; при автоматическом вращении сохранён прежний лимит 30. Это программные лимиты, а не гарантия FPS устройства.
- Переключение режима качества не переразмеривает framebuffer, если вычисленное разрешение не изменилось.
- Автовращение карточек сохранено по прямому указанию пользователя. Геометрия, освещение, сетка, камера и интерфейс не менялись.

## Подтверждённый результат

Chromium, 1440×1050, SwiftShader:

| Режим | Размер framebuffer | Пикселей |
|---|---:|---:|
| До изменения | 2135×1217 | 2 598 295 |
| Вращение после изменения | 1146×654 | 749 484 |
| После отпускания, экран 2× | 2135×1217 | 2 598 295 |
| После отпускания, экран 1× | 1180×673 | 794 140 |

Во время движения объём пикселей меньше примерно на 71%. Это не означает ускорение всего сайта или GPU в 3,5 раза: количество draw calls (66 в проверенном первом проекте) и геометрия не менялись.

Сырые замеры: before.json / after.json. Программный SwiftShader даёт очень низкий и нестабильный FPS (3 кадра за ~4 с до, 5 за ~4,4 с после); эти короткие выборки не подходят для обещаний скорости на компьютере пользователя. Время JS-вызова render не является временем завершения работы GPU. Целевой физический компьютер, его видеокарта и браузер пока не измерялись.

retina.json подтверждает реальный жест мышью, снижение разрешения и его восстановление, errors: []. Снимок night-restored.png получен после жеста и восстановления разрешения; ракурс изменён самим жестом, материалы не менялись. Шрифты системные: внешняя загрузка отключена в тесте.

## Проверки

npm test — PASS: тарифы, геометрия, DOM, навигация, fallback без WebGL, режимы моделей, дневной/ночной свет, выбор IFC.

Дополненные scene-тесты проверяют:

- отсутствие навязанного 2× на обычном экране;
- уменьшение и возможность восстановления pixel ratio на high-DPI;
- разрешение примерно 60 отрисовок за секунду при модельном 60 Hz потоке событий и прежний бюджет около 30 в покое;
- сохранение вращения карточек.

Физические мобильные устройства и полевые Web Vitals в этом проходе не проверялись. Для дальнейшего FPS потребуется профиль на компьютере пользователя; при необходимости можно уменьшать draw calls/стоимость материалов, сохраняя согласованный вид. Переписывание на Rust и Figma для этих изменений не нужны.
